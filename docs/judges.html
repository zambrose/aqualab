The instruction pipeline — composition, not a monolith

A strategy is a byte program of [opcode][len][args] triples. Byte order is outermost-wrapper-first, and it encodes real execution nesting: Decay( Fee( Swap ) ).

Controls._saltunique strategy hash · no-op
Decay._decayXDMEV protection · virtual-balance decay (outer wrapper)
Fee._flatFeeAmountInXDLP fee on input (inner wrapper)
XYCConcentrate._xycConcentrateGrowLiquidity2Dprices the trade (leaf)
OpcodeRoleWhy it's here
_xycConcentrateGrowLiquidity2DConcentrated CPMMFocuses liquidity into a price band → deeper book → better price than plain x·y=k at equal reserves.
_flatFeeAmountInXDLP feeTakes bps off the input before the curve prices it; accrues to the maker.
_decayXDMEV protectionA trade leaves a decaying offset, so a same-direction follow-up costs more — front-running is penalized.
_saltuniqueness no-opLets otherwise-identical pools ship as distinct immutable Aqua strategies.

Ordering is enforced, not conventional

Fee and Decay are wrapper instructions that run the rest of the program via runLoop(); the AMM is a leaf. Both assert the swap hasn't priced yet, so the curve is forced innermost — putting the swap first reverts. Full mechanics in the explainer →

The upstream 1inch CoreInvariants battery runs against our composed strategy through real swaps: symmetry, quote/swap consistency, monotonicity, rounding-favors-maker, and balance-sufficiency all pass. Additivity is intentionally configured off — under _decayXD price is path-dependent by design, so it is genuinely not an invariant of the pool.

The visualizer — a debugger for the VM

SwapVM has five registers. Most demos show only the final input and output. AquaLab shows the registers mutating after every instruction — the thing that makes the composition legible.

The finding that shows our depth

The deployed SwapVM router is newer than any published source

The live router at 0x8fDD04…0958f (22,640 bytes) is a later build than release 0.0.6 — its opcode table has a _progressiveFeeInXD instruction the published sources don't, with shifted indices. So a program built against pinned 0.0.6 bytes can't execute on it. Rather than paper over this, we verify the discrepancy on-chain: a test asserts the canonical router is live, that its AQUA() equals the same live Aqua we ship into, and that its bytecode differs from our pinned build (18,142 bytes). We execute on a self-deployed 0.0.6 engine for reproducibility, while using the real live Aqua liquidity layer — and we document the dev-preview version skew honestly. For a ~7-month-old preview protocol, finding and reasoning about that gap is the point.
